## 2. 评测管线

入口：`heatrad/eval/run_eval.py`（推理+指标） / `heatrad/eval/rescore.py`（只跑指标）。
预处理：训练数据带 prompt 前缀 `"Generate a chest CT report ... Report:\nFindings:"`，模型在推理时会复读这段，需在评测前用 `strip_prompt_prefix()` 砍掉以 `Findings:` 为锚的部分（参考也同样处理，对齐）。

## 5. 评测踩坑与修复

| 坑 | 修复 |
|---|---|
| hyp 头部复读训练 prompt 前缀，NLG 虚高 | `strip_prompt_prefix()` 砍 `Findings:` 之前的内容；ref 同处理 |
| `transformers` 安全检查拒绝 torch < 2.6 加载 `.bin` 权重，导致 RaTEScore 失败 | BioLORD-2023-C 手动 `torch.load` → `safetensors.save_file`，落地 `model.safetensors` |
| `f1chexbert` 预期 `~/.cache/chexbert/chexbert.pth` 在 cache_dir 根，实际下载到 hub blob 子目录 | 软链 blob 到 `chexbert.pth` |
| `f1chexbert` 慢 tokenizer 路径依赖 protobuf，未装 | `pip install protobuf sentencepiece` |
| hydra 子进程默认 ascii 编码，写带 em-dash 的 JSON 时 `UnicodeEncodeError`，summary 写一半被截断 | `open(out_path, "w", encoding="utf-8")`；启动时 `PYTHONIOENCODING=utf-8 LC_ALL=C.UTF-8` |
| `HF_HUB_OFFLINE=1` 阻止 RadGraph 版本校验，触发失败 | 让 RadGraph 联网校验一次（其余仍 offline，避免 HF mirror 与原站文件不一致） |
| hf-mirror.com 与 huggingface.co 上 BioLORD-2023-C 文件列表不一致（mirror 缺 `pytorch_model.bin`），导致首次评测 RaTE 加载失败 | 不用 mirror 取该模型；保留 mirror 仅用于下载快但文件完整的仓库 |

## 7. 观察到的失败模式（看 hyp 例子）

- 模型在很多 case 上输出**模板化报告**（"Trachea and both main bronchi are open. No occlusive pathology..."），尤其是与训练集众数相近的"无显著异常"型样本，与 ref 偏差大时 NLG / CE 都低。
- 罕见或重病例（如多发转移、肿块、Covid-19 浸润）召回明显不足，RadGraph-complete 仅 0.146 反映关系级别匹配很弱。
- `val_3_a_1`、`val_4_a_1` 等多个 case hyp 几乎完全重复（生成坍塌到同一段模板）。属于 LoRA 训练数据偏置 + greedy 解码的典型表现。

## 8. 下一步候选

1. **解码改造**：beam search / sample + length_penalty，看 NLG/CE 是否能拉 2–3 个点；
2. **生成坍塌问题**：训练时按 organ-bag dropout schedule 让模型对视觉前缀更敏感，但 inference 时 prefix 应该信息更丰富。需检查 inference 阶段 sparsemax π 分布、α 分布、abstain 概率是否退化；
3. **可视化**：α 沿切片轴的曲线 + 每器官 sparsemax 选片图，配 demo；
4. **GREEN 指标**（LLM-based）补一组对比；
5. **训练侧**：训练时把 prompt 前缀的 token loss mask 掉（label=-100），避免模型学到复读 prompt——下一轮 finetune 可直接修。
